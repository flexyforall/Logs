# GRU Space: как делать презентации в нашем стиле

Инструкция снята с презентаций в Figma-файле **GRU-Space → 📂 Brand Assets** (`yZhobDQuNGYEfdymtRczRp`).
Эталон — страница **↳ Presentation.New** (91 слайд). Сверялся также с Presentation.1–3, GRU × ADIDAS, GRU × OMEGA,
GRU x LSA и Tech Tree. Цифры ниже — фактические значения из узлов Figma, а не «на глаз».

Последняя дека, собранная по этой инструкции: страница **↳ GRU × NASA Moon Base**, лежит сразу после Presentation.New.

---

## 1. Формат и сетка

| Параметр | Значение |
|---|---|
| Слайд | Frame 1920 × 1080, фон `#000000` (изредка `#020202`), Clip content |
| Где | Новая страница `↳ <Название>` внутри группы Brand Assets, рядом с Presentation.New |
| Поля | 60 px слева и справа → контентная ширина 1800 |
| Заголовок | Верх заглавных букв (cap height) на **y = 72**, x = 60 |
| Знак «+» | Компонент `Icon` (`747:1105`, UI Kit) 27 × 27, белый 50 %, в точке **(1833, 72)** на каждом слайде |
| Контентная зона | y = 380 … 960, одинаковая на всех слайдах, даже если заголовок однострочный |
| Футер | Оговорка/источник слева (x 60, cap ≈ 1000), номер слайда справа (до x 1860) |
| Колонки | 3 × 600 (границы 660 / 1260) или 2 × 900 (граница 960); зазор между карточками 30–60 |
| Обложка | Лого-штамп GRU 120 × 120 в (60, 60), большой заголовок в нижней половине слева |

Пустое место под заголовком — нормально: бренд держит воздух, контент всегда начинается с одной линии.

## 2. Типографика

Два шрифта и ничего больше: **Overused Grotesk** (рабочий) и **PP Mondwest** (характер, вторые половины фраз, цифры, лейблы).

| Роль | Шрифт | Кегль / интерлиньяж | Цвет |
|---|---|---|---|
| Заголовок, часть 1 | Overused Grotesk Regular | 90 / 100 %, трекинг −2 % | white 100 % |
| Заголовок, часть 2 | PP Mondwest Regular | 96 / 100 %, трекинг −2 % | white 60 % |
| Заголовок обложки | те же пары | 104–160 / 100 % | как выше |
| Подзаголовок | Overused Grotesk Regular | 28 / 140 % | white 60 % |
| Крупный текст | Overused Grotesk Regular | 40 / 140 % | white 100 % или 60 % |
| Основной текст | Overused Grotesk Regular / Book | 28 / 140 % | white 60 %, ключевые слова white 100 % |
| Подпись, оговорка | Overused Grotesk Regular | 20 / 28 px | white 40–45 % |
| Лейбл | PP Mondwest Regular, UPPERCASE | 24 / 30 | white 50–60 % |
| Номер в пилюле | PP Mondwest Regular | 28 | white 100 % |
| Акцентная цифра | PP Mondwest Regular | 120–160 | white 100 % |
| Подзаголовок колонки | PP Mondwest Regular | 40 | white 100 % |

Правила:
- Заголовок всегда двухтональный: первая часть Grotesk белым, продолжение Mondwest 60 %.
  Переносить строку явно, Mondwest уходит на вторую строку: «Our ride to the Moon / *is contracted*».
- Выделение внутри абзаца — только цветом (100 % против 60 %), без жирного.
- Цифры, ID, годы и лейблы — Mondwest; объяснения — Grotesk.

## 3. Цвет и линии

Палитра монохромная, акцент — чистый белый против приглушённого.

| Элемент | Значение |
|---|---|
| Фон | `#000000` |
| Текст | white 100 / 60 / 45 / 40 % |
| Волосяные линии сетки | white 10–12 %, 2 px, со знаком «+» на пересечениях |
| Рамки карточек и таблиц | stroke 2 px inside, white 16 % |
| Акцентная карточка | fill white 5–6 % + stroke 24 % |
| «Стеклянная» карточка поверх фото | fill white 5 %, stroke 16 %, radius 20 |
| Пилюля | stroke white 12 %, radius = h/2, высота 52 |
| Пилюля поверх фото | fill black 45–55 % + stroke white 30 % |
| «Не основное» или «не оплата» | пунктир (dash 10/8), stroke 20 % |
| Затемнения поверх фото | чёрный линейный градиент 100 % → 0 % |

## 4. Компоненты

- **Пилюля-лейбл**: Mondwest 24 UPPER внутри капсулы. Используется для статусов (`Discussions`), фаз (`Phase One`) и подписей на фото (`GRU concept render`, `Japan meeting photo`).
- **Номер-пилюля** 84 × 52 с `01`…`04` Mondwest 28 — у списков, шагов и строк таблиц.
- **Список-строки**: между пунктами горизонтальные линии 10–16 %, номер слева, текст справа (Grotesk 28 или 40).
- **Таблица**: внешняя рамка 16 %, строка заголовка с заливкой 5 % и лейблами Mondwest UPPER, вертикальные разделители 16 %, горизонтальные 10 %.
- **Таймлайн/роадмап**: горизонтальная линия на всю ширину, «+» на пересечениях, фазы в пилюлях, годы Grotesk 64.
- **Стрелки** — тонкие линии 2 px, white 60–70 %, наконечник `ARROW_LINES`. Должны оставаться редактируемыми векторами.
- **Лого-штамп** — клон узла `2731:644`, только на обложке.

## 5. Изображения

- Рендеры и фото даются крупно: на всю ширину (full-bleed) или крупным блоком. На тёмных рендерах текст кладётся слева, поверх градиента.
- Вырезанное железо (cutout PNG) — на чистом чёрном, без подложки.
- Реальное фото подписывается пилюлей на самом фото: что это и откуда.
- Концепт-рендер **обязательно** помечается пилюлей `GRU concept render` / `Concept`.
- Не генерировать людей, железо и встречи. Если фото нет, факт подаётся текстом.
- Фирменные фоны (Луна, горизонт) уже есть в файле, их берём по `imageHash`:
  `442db942…` (горизонт с солнцем, 4096 × 2286), `b6597f65…` (лунный шар, 1920 × 1920).

## 6. Контент и честность

- Одна мысль на слайд, обычно не больше 40 слов основного текста.
- Статусы и оговорки («target», «proposed», «concept», «not a NASA selection») остаются на слайде, в футере.
- Источники, ссылки и подробные оговорки — в блоке **Speaker notes** под фреймом (Inter 22/32, не входит в слайд).
- Пометки конфиденциальности (например, Blue Origin Proprietary & Confidential) не убираются.
- Бэкапы отделяются слайдом-разделителем `Backup` с оглавлением; номера бэкапов — `Backup · 11`.

## 7. Как собирать (заметки для себя)

**Шрифты.** Overused Grotesk и PP Mondwest — локальные шрифты дизайнеров. В облачном рантайме Figma (MCP `use_figma`)
их нет, и `loadFontAsync` падает. Обход:

1. Создать текст в Inter (загружается), задать символы, ширину, выравнивание и заливки по диапазонам (`setRangeFills`).
2. Применить существующие текстовые стили файла по диапазонам: `setRangeTextStyleIdAsync`. Для этого шрифт грузить не нужно.
3. `node.rescale(k)` доводит кегль; интерлиньяж и абзацный отступ в px масштабируются вместе с ним.

| Роль | Стиль файла | k | Итог |
|---|---|---|---|
| Заголовок | H2-OG (56/62) + H2-PP (60/62) | 90/56 = 1.607 | OG 90 + MW 96.4, строка 99.6 |
| Обложка | H2-OG + H2-PP | 104/56 … 150/56 | |
| Текст 28/140 | B2-regular (20/28) | 1.4 | 28 / 39.2 |
| Текст 40/140 | B2-regular | 2.0 | 40 / 56 |
| Подпись | B2-regular | 1.0 | 20 / 28 |
| Лейбл | U1-PP-regular (16/20, UPPER) | 1.5 | MW 24 / 30 |
| Номер | C1-PP (16/20) | 1.75 | MW 28 / 35 |
| Подзаголовок колонки | C1-PP | 2.5 | MW 40 / 50 |
| Акцентная цифра | H1-PP (64/72) | 1.25–2.35 | MW 80–150 |
| Grotesk-дисплей | H1-OG (64/72) | 1.0–1.31 | OG 64–84 |

Ограничения обхода:
- Трекинг и leading trim берутся из стиля: 0 % и none. Брендовые −2 % на заголовках дизайнер ставит в десктопе одним действием.
- Облачные скриншоты показывают текст заглушкой. Вёрстку проверяем локальным превью (`render_preview.py`, Chromium + настоящие шрифты).
  В десктопном Figma с установленными шрифтами текст перерисуется. Если какой-то слой остался «старым», достаточно выделить текст и поменять любое свойство.

**Картинки.** `upload_assets` шлёт байты на `mcp.figma.com`. Если сеть окружения этот хост не пускает, подставляем
`imageHash` картинок, которые уже лежат в файле, а остальные плейсхолдеры (`img/<имя>`) заполняем вручную.

**Пайплайн кита** (`gru-deck-kit/`):
1. `gru_kit.py` — токены, роли, конструкторы элементов, перенос строк по реальным метрикам шрифтов, аудит переносов.
2. Модуль деки (контент конкретной презентации) пишет `out/spec.json`. Контент деки в git не кладём: репозиторий публичный.
3. `render_preview.py <deck_module>` — HTML → PDF через Chromium с брендовыми шрифтами и нарезка картинок под плейсхолдеры.
4. `figma_build.py <pageId> <batch> …` — генерирует скрипты `use_figma` пачками примерно по 4 слайда (≈20 тыс. символов).
